# Windows Backup Monitor for Zabbix 7.0

Read-only, local backup job monitoring for **Zabbix Agent 2** on Windows. The collector supports Veeam Agent for Microsoft Windows through its local Event Log and SQL Backup Master 8.x+ through the vendor PowerShell cmdlets, including direct loading of `SQLBackupMaster.Cmdlet.dll` when PowerShell cannot auto-discover it. It supports multiple jobs per host, one JSON master item, summary items, and per-job low-level discovery.

> The collector verifies the state reported by the local backup software. It does not verify that backup files are readable or restorable.

It does not access a repository or network share, require repository credentials, start or stop jobs, change schedules, or perform restores. All collector operations are local and read-only.

## Install

1. Copy `src/windows-backup-monitor.ps1` to `C:\Program Files\Zabbix Agent 2\scripts\windows-backup-monitor.ps1`.
2. Include `zabbix/windows-backup-monitor.conf` in `zabbix_agent2.conf` (or copy its `UserParameter` line into an existing included file).
3. Ensure the Zabbix Agent 2 service account can read the **Veeam Agent** Event Log and use the SQL Backup Master module. Test in that account's security context.
4. Import `zabbix/zabbix_template_windows_backup_monitor.yaml` into Zabbix 7.0 and link the template to the host.

The configured command uses `powershell.exe -NoLogo -NoProfile -NonInteractive -File` and does not bypass execution policy. Set an appropriate Windows execution policy and sign the script if your organization requires signing. See [setup details](docs/ZABBIX_SETUP.md).

## Run locally

```powershell
powershell.exe -NoLogo -NoProfile -NonInteractive -File .\src\windows-backup-monitor.ps1
powershell.exe -NoLogo -NoProfile -NonInteractive -File .\src\windows-backup-monitor.ps1 -Provider SqlBackupMaster
powershell.exe -NoLogo -NoProfile -NonInteractive -File .\src\windows-backup-monitor.ps1 -VeeamLookbackDays 30
```

The default `Auto` mode queries both providers. Veeam Event Log lookback defaults to 30 days, and the Zabbix master item runs once an hour. A selected provider mode includes only that provider in the JSON. Exit code `0` means a valid JSON document was written, including when a provider has `ok=false`; collector-level failures use codes `2`, `3`, and `4`.

Example (timestamps and UID are illustrative):

```json
{"schema_version":1,"collected_at_epoch":1790334000,"providers":[{"provider":"veeam-agent","detected":false,"ok":true,"error":null},{"provider":"sql-backup-master","detected":true,"ok":true,"error":null}],"jobs":[{"provider":"sql-backup-master","job_uid":"sql-backup-master-94e40410bb29b229278310aab82c000a","job":"ENOVA","enabled":true,"running":false,"status_code":1,"status":"Success","last_start_epoch":1790330400,"last_finish_epoch":1790332200,"last_success_epoch":1790332200,"last_success_age_seconds":1800,"duration_seconds":1800,"next_run_epoch":null}]}
```

Status codes: `0 Unknown`, `1 Success`, `2 Warning`, `3 Failed`, `4 Running`, `5 Canceled`, `6 NeverRun`, `7 Disabled`. Unavailable times are JSON `null`, never epoch zero. Job UIDs are SHA-256 of provider + NUL + job name, truncated to 16 bytes. A rename changes the UID and creates a new discovered item.

## Tests and current validation

Run the included Pester suite with Windows PowerShell 5.1:

```powershell
Invoke-Pester -Path .\tests\windows-backup-monitor.Tests.ps1
```

The test suite uses synthetic fixtures plus a sanitized positional Veeam Event XML layout captured from a real host, and mocked SQL cmdlets. The Zabbix template is generated by `tools/generate_template.py`; the GitHub workflow checks syntax, tests, template structure, ZIP contents, and hashes.

After a GitHub release is published, `.github/workflows/release.yml` builds the ZIP from that release tag and automatically attaches the ZIP and `SHA256SUMS.txt` to the existing release.

Before production use, capture sanitized XML from a real Veeam Agent host, inspect real SQL Backup Master job and status objects, test under the Zabbix Agent 2 service account, and import the YAML into a real Zabbix 7.0 server. These environment checks are still required for v1.0 sign-off.

## Limitations

- Veeam discovery uses retained Event Log records within the configured lookback. A configured job with no event, or a job whose events have rolled off, is not discovered.
- Veeam positional EventData parsing is validated against sanitized real 110/190/191 records. It depends on the documented English Veeam Agent message format for extracting the job name/status when named XML fields are absent.
- The SQL status adapter accepts candidate field names, but exact output properties must be checked on SQL Backup Master 8.x+. Unknown optional fields stay `null` or `Unknown`.
- SQL Full, Differential, and Transaction Log schedules remain one job in v1.
- No backup file integrity or restore verification is performed.

See [provider mapping and validation](docs/PROVIDERS.md) and [Zabbix setup](docs/ZABBIX_SETUP.md).
